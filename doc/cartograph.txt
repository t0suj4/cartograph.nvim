1. INTRODUCTION                                       *cartograph-introduction*

Cartograph is a keyboard-driven Smalltalk-style system browser for your
codebase — plus the thing Smalltalk's browser lacked: TRANSACTIONS. It
extracts a symbol graph (functions, methods, vars, calls, imports) with
tree-sitter, renders it as an altitude browser (files -> file -> function ->
statements) beside real source, and lets you stage multi-file edits — merge
clones, move functions, extract modules — that preview as diffs, apply
through a journal, and undo byte-exact.

Sixteen languages ship specs (lua, c, cpp, python, javascript, typescript,
php, ruby, java, go, rust, haskell, scheme, zig, odin, bash) plus vue/svelte
single-file components. Everything cross-file is name-matched and marked `~`
unless an oracle proved it; ambiguity refuses to link rather than guess.

Status: EXPERIMENTAL. Tested and journaled (edits undo byte-exact), but
commands, keys and APIs may change without notice.

2. QUICKSTART                                           *cartograph-quickstart*

No setup call is required. Open a project: >

    :Cartograph              " the current working directory
    :Cartograph ~/src/proj   " any directory
    :Cartograph dump.json    " a pre-extracted graph dump
    :Cartograph mcp://name   " a graph served over MCP (setup{ mcp = ... })
    :Cartograph self://loaded " this nvim's own loaded plugins as a graph
<
The layout is symbols (left) | source | plan bar (bottom). In the symbols
pane: `l` descends, `h` ascends, `<CR>` pivots. Hover previews; movement
never changes focus — pivots are conscious.

To move a function: `dd` on its row cuts it into the move-set, `p` on a
file row sets the destination, then >

    :CartographMove          " plan the transaction
    :CartographDiff          " the exact bytes it would write
    :CartographApply         " journal-first commit
    :CartographUndo          " byte-exact rollback
<

3. COMMANDS                                               *cartograph-commands*

All commands exist at startup; those that need an open graph say so. Two are
PANE-LOCAL — they exist only in the buffer they act on, and say which.

OPENING AND SESSIONS                                      *cartograph-cmd-open*

  :Cartograph [target]        open the cockpit (dir | dump | mcp://name)
  :CartographIndexOnly [dir]  open in index-only mode: a thin symbol
                              index for LSP and navigation, no analysis.
                              Analysis artifacts fill in ON DEMAND, per
                              file (dataflow, calls, id pass), and the
                              call-graph verbs refuse only while that
                              coverage is PARTIAL — once every file is
                              covered they answer normally. The graph
                              still remembers it began thin, so it is
                              never served from cache as a full open.
  :CartographRefresh[!]       re-extract current file (! = whole project)
  :CartographBands            list the open bands (multi-band session)
  :CartographSwitch {band}    switch the active band
  :CartographSelf             declared vs live registrations (the
                              self:// oracle)
  :CartographLspAttach        attach the in-process LSP read surface to
                              this buffer
  :CartographLspDetach        stop the in-process LSP read surface

NAVIGATING AND OVERLAYS                                    *cartograph-cmd-nav*

  :CartographCone [depth]     reachability cone on the cursor node
                              (in = ancestors, out = descendants)
  :CartographTerritory        territory overlay — partition the graph by
                              which entry points reach each node
  :CartographSpines           the tree structures hiding in the graph
                              (call-dominator + subsystem)
  :CartographHeat             toggle the hub/heat overlay: fan-in/out
                              and role (symbols pane only)
  :CartographMark             toggle the cursor row's subject in the
                              working set (see |cartograph-subject|)
  :CartographWorkingSet       open the working-set view
  :CartographWorkspace        open the workspace — ad-hoc Lua against
                              the loaded graph; a returned node list is
                              browsable
  :CartographEval {lua}       evaluate Lua against the graph
                              (store/spines/territory/… in scope)

HONESTY AND RESOLUTION                                 *cartograph-cmd-honesty*

  :CartographCensus           epistemic census — edge trust tiers and
                              refusals by rule (the analyzer work-list)
  :CartographLadder           the call graph's epistemic distribution
                              (proven / linked / ~ / dynamic / refused /
                              frontier) + the heaviest refusals to resolve
  :CartographMentions [name]  which files MENTION a name — the word under
                              the cursor by default. Reads the mention
                              index (each file's identifier set, recorded
                              by the id pass) rather than the call graph,
                              so it still answers where RESOLUTION
                              REFUSED: a refused call tells you nothing
                              about the target but still tells you the
                              name occurs. REFUSES when the graph has no
                              mention index — the THIN INDEX has none,
                              since index_only skips the pass that builds
                              it — rather than reporting zero mentions,
                              which would be a fabricated negative.
                              NAME-LEVEL EVIDENCE, never
                              references: a mention is an identifier
                              OCCURRENCE, and nothing here claims two
                              files name the same thing — the report says
                              how many defs share the spelling, because
                              that is what decides whether the evidence
                              means anything. Per FILE, never per line:
                              the index interns each name once per file,
                              so a per-site answer does not exist at this
                              altitude and is not invented. SCOPE-
                              CONFINED to the asking file's resolution
                              scope, the same cut resolution makes — so
                              the list is the candidate set a resolver
                              would consider, not every file sharing a
                              spelling. When a call graph IS present the
                              resolved subset is marked as a SUBSET (`=`
                              resolved, `~` mention only), leaving the
                              residual visible instead of hidden; on the
                              thin index that subset reads "unavailable",
                              never "none".
  :CartographVersionFloor     which language version this code NEEDS, as
                              an attributed SET: the feature and site
                              holding the floor up, not a bare number.
                              Plus the DOWNGRADE LADDER — what supporting
                              each older version would cost, in sites to
                              fix. TWO TIERS, never mixed: the floor and
                              the ladder are CERTAIN (syntax in the tree),
                              while version-gated stdlib CALLS ride below
                              as `~` — a name match can't see its
                              receiver's type. A stdlib name the project
                              also defines resolves there instead, so the
                              hedged tier under-reports and says so.
                              Compares the floor against what the project
                              DECLARES (gemspec / Gemfile / pyproject /
                              setup.py / tsconfig target): computed newer
                              than declared is a BROKEN PROMISE with the
                              site named; computed older is explicitly
                              NOT a finding, since the floor is a lower
                              bound. One section PER SCALE — ruby 3.1 and
                              ECMAScript 2022 are different rulers and
                              are never maxed together. The answer is a
                              RANGE: a name a later version REMOVED gives
                              a CEILING, so the report ends at
                              [floor, ceiling) — and says NO VERSION
                              WORKS outright when the two ends cross.
                              A behaviour CHANGE is neither end: it SPLITS
                              the range, so it is reported only when the
                              range straddles it (the same code doing two
                              things), and noted as outside when not
  :CartographRequires         the code's OWN profile — the inverse of an
                              environment one, in the same currency: the
                              external names it needs plus its version
                              floor, as ONE requirement set. Over that
                              set: the TIGHTEST ENVIRONMENT (shipped
                              profiles ranked by coverage) and the
                              DEPENDENCY MANIFEST (the set grouped by who
                              provides each name). Coverage, never a
                              verdict; an artifact that cannot answer
                              name queries says so instead of scoring 0%
  :CartographPortability[!] {runtime} [{to-runtime}]
                              score the external surface against a target
                              environment profile (tab-completes the ones
                              that ship): which names it PROVIDES, and
                              which are NOT IN it, with call counts, GROUPED
                              BY WHY the artifact cannot adjudicate them.
                              The header names BOTH ends when the package
                              manifest declares a target, so it states a
                              MOVE. "Not in the profile" is NOT "missing":
                              a dependency may supply it, or the artifact
                              may be partial, so the profile's own size is
                              printed with the verdict. A profile for
                              another language is refused rather than
                              scored. With TWO runtimes it diffs the MOVE
                              from the first to the second: the names whose
                              status changes ARE the porting work (needs
                              two same-language profiles that answer name
                              queries: luajit/lua-factorio, ruby-core/
                              ruby-rails, lua-factorio-11/lua-factorio).
                              ! also reports the READ surface — names
                              touched but never called, where `global.foo`
                              and `game.x[...]` live; opt-in because it
                              re-parses every function
  :CartographExternals        the external boundary — unresolved names
                              and the shape each use implies (~)
  :CartographRoster [{ecosystem}] [{dir}]
                              the package ROSTER of an INSTALLED ecosystem
                              (default lua-factorio; tab-completes the ones
                              that ship): packages by form, which of them
                              LOAD, both cheap guesses at identity scored
                              against the manifest, and every declared
                              dependency judged against this install.
                              Findings split ACTIVE vs LATENT by
                              enablement — a conflict between two disabled
                              packages is a fact about the install, not a
                              fault in it. Reads a DIRECTORY, not a graph,
                              so it needs no extraction; a large mods dir
                              costs seconds. A root the spec marks not
                              derivable is reported unspecified rather
                              than guessed (see |cartograph-config|
                              `ecosystem_roots`), and an ecosystem with no
                              declared package forms is REFUSED rather
                              than reported as an empty install
  :CartographEscalate[!]      escalate hedge-saturated fns to lua-ls
                              (async): confirmed / CONFLICT / refuted /
                              recovered. ! = the whole graph
  :CartographFieldHarvest     disagreement harvest — our self.field
                              read→write links vs lua-ls go-to-definition.
                              A CONFLICT is a real bug on ONE side
  :CartographAudit            diff the live indexes against a fresh
                              derive (catches in-place writer drift)
  :CartographDogfood          the self-analysis dashboard, with the LSP
                              read surface attached
  :CartographDiscover[!] [verb]
                              explain registry auto-discovery (! deep tier)
  :CartographShapes           explain project-shape detection for this root
  :CartographFeedback[!] [text]                       *cartograph-cmd-feedback*
                              file feedback ABOUT CARTOGRAPH, frozen at the
                              node you are standing on. You type only what you
                              EXPECTED; the observed half is captured — the
                              rendered rows verbatim, the gesture you pressed
                              and the rows it was pressed on, the subject's
                              frozen source, the typed empty as rendered, call
                              provenance, and the environment facts that decide
                              verdicts (parsers on the runtimepath, profile,
                              packs, index-only, cache VERSION, commit). With
                              no argument it opens a compose buffer with
                              git-commit semantics: # lines are stripped, :w
                              files it, :q abandons it. An entry FREEZES and
                              never re-anchors, because an anchor repaired
                              after an edit silently points at different code.
                              Fileable with no graph loaded and on a row with
                              no node — an absence is the most useful report
                              there is. One JSON per entry under
                              stdpath('state'): a user record, never a cache.
                              ! = dump every entry for this root as pasteable
                              markdown

ANALYSING THE FOCUSED FUNCTION                        *cartograph-cmd-analysis*

  :CartographFields           field/member linker — resolve this
                              method's self.field reads to the write(s)
                              on its class (own methods + extends
                              ancestors). A writeless read stays
                              unresolved
  :CartographPrototypes[!]    the DATA STAGE: every prototype the
                              project declares, read as a base
                              reference + an ORDERED sequence of field
                              overrides + its registration — which is
                              what a prototype is, not a table literal.
                              Reads module-TOP-LEVEL rows. Honest about
                              being a lower bound: an opaque call
                              receiving the prototype marks it ~HEDGED,
                              a non-literal value keeps its path and
                              records why, an unresolved base names the
                              local to follow, an explicit nil is a
                              DELETE. Needs an env profile with a data
                              stage (today: lua-factorio) and says so
                              when there is none. WITH A BANG the same
                              records open in the browser instead: a
                              roster you descend for one prototype's
                              ordered overrides, hover to preview the
                              declaring line, h back out. The rows carry
                              paths and markers (∅ delete, ? unread, ~
                              hedged) but no VALUES — those are in the
                              source one hover away, and in the report
  :CartographTrace [n]        where parameter [n] (default 1) gets its
                              values: one row per resolved call site,
                              |cartograph-keys| descend takes the next
                              hop, pivot reveals the site. `▸` has a
                              next hop, `~` is a frontier that says why
                              it stops (field/global aliasing, a dynamic
                              call, varargs), `·` is an answer
  :CartographBranchValues     the values live through each CFG branch
                              (~ = hedged reaching)
  :CartographNarrow           where a guard proves a variable non-nil in
                              a region (branch-sensitive narrowing)
  :CartographParamNil         inferred parameter nilability (required /
                              optional / unknown) against the ---@param
                              annotations; an unguarded deref of a
                              nilable `?` param is a real defect
  :CartographDevirt           method dispatches whose receiver a guard
                              narrows to a concrete type — the
                              static-call candidates
  :CartographExpr             expression lints: self-compare, duplicated
                              operand, bool-comparison, self-assignment,
                              pseudo-ternary, constant condition,
                              concat-in-loop, duplicated condition
  :CartographReorder          statement commutativity: deps, conflicts,
                              freely-movable rows. <CR> reveals the
                              statement in the source pane
  :CartographOptimize         loop-invariant computations (LICM): pure
                              work hoistable above the loop. * = clean,
                              ~ = aliasing- or branch-hedged
  :CartographUntangle         independent concerns over the
                              data+control+effect PDG, with the
                              safe-to-split verdict and its why-not
  :CartographUntangleModule [dir]
                              independent function clusters in this file
                              — or a directory, for god-package scope —
                              over call + shared-written-state edges
  :CartographExtractBlocks    this function's control sub-regions
                              (loops/branches) as helper candidates,
                              each with its (params)->(returns)
                              interface and control-escape verdict

REFACTORING                                           *cartograph-cmd-refactor*

Each of these STAGES a transaction and writes nothing: review with
:CartographDiff, commit with :CartographApply (|cartograph-cmd-txn|). What a
verb refuses is as load-bearing as what it writes — see
|cartograph-transactions|.

  :CartographMerge            merge the focused function's clones
  :CartographMove             the cut/paste move-set (dd cuts a row, p
                              on a file row sets the destination)
  :CartographExtractModule {path}
                              extract the move-set into a NEW file
  :'<,'>CartographExtract {name}
                              extract the selected lines into a function
                              (source pane only)
  :CartographExtractHelper    propose the parameterized helper this
                              function and its nearest near-clone could
                              factor into — the anti-unified template
                              plus a body-safety verdict. A scaffold to
                              read; nothing is staged
  :CartographExtractHelperApply [path]
                              stage that helper for real. A same-file
                              pair needs no argument; a CROSS-FILE pair
                              takes a destination module path. Held to
                              the sound subset; refuses outside it
  :CartographHoistClosure     lift the focused NESTED closure to module
                              scope — sound only when it captures
                              nothing. Refuses a capture, naming the
                              variable
  :CartographReorderApply {from} [through] {to}
                              move statement {from} — or the block
                              {from}..{through} — to before {to}, if the
                              commute verdict certifies it
  :CartographOptimizeApply    dry-run the CSE-reuse rewrite: the exact
                              diff an apply would write, journaled and
                              CAS/span/parse-verified
  :CartographNeutralitySnapshot
                              capture the per-function behavior
                              witnesses (df shape + params + callees) as
                              a baseline
  :CartographNeutralityCheck  diff the witnesses against that baseline —
                              neutral = a pure move, DRIFTED = the body
                              changed. Certifies a relocation; honestly
                              flags a rewrite

4. KEYS                                                       *cartograph-keys*

Every binding is remappable. The FIELD column is the name to pass to setup —
any subset, and `false` unbinds one entirely: >

    require('cartograph').setup {
      keys = { descend = '<Right>', close = false },  -- false unbinds
    }
<
Defaults assume qwerty and reuse standard vim idioms (tags, jumplist, gf).
This table is checked against lua/cartograph/config.lua by tools/docaudit.lua,
so it cannot drift from the code.

NAVIGATION ~
  field         default   what it does ~
  pivot         <CR>      re-root on / expand this entry
  jump          <C-]>     source: go to the callee under the cursor
  back          <C-o>     jumplist back
  back_alt      <C-t>     also back, where <C-o> is already taken
  forward       <C-i>     jumplist forward
  open_file     gf        open the real file at this entry
  ascend        h         symbols: zoom out (function -> file -> tree)
  descend       l         symbols: zoom in
  down          j         symbols: next row; at a block's last row it
                          steps OUT to the parent
  up            k         symbols: previous row, mirrored upward
  cycle         <Tab>     cycle this altitude's lens (|cartograph-lenses|,
                          which the pane's winbar names for you)
  cycle_back    <S-Tab>   cycle it the other way
  close         q         close a pane

STAGING (symbols pane) ~
  field         default   what it does ~
  cut           dd        cut this row into the move-set
  cut_visual    d         cut the visual selection
  paste         p         on a file row: set the destination
  unstage       u         unstage the last cut

NODE MARKS (symbols pane) ~
  field         default   what it does ~
  set_mark      m         remember the node under the cursor, m{a-z}
  goto_mark     `         pivot to a remembered node, `{a-z}

Marks are the one working-set-adjacent thing that IS a vim idiom, so they keep
the key: the meaning matches vim exactly, but they are keyed by NODE, not line.

UNBOUND BY DEFAULT                                    *cartograph-keys-unbound*

A graph operation with no vim idiom behind it does not squat on a vim key — `m`
already marks, `M` is already middle-of-screen. These ship as COMMANDS and stay
unbound until you ask for them:

  field         default   what it does ~
  mark          (unbound) toggle this row's SUBJECT in the working set,
                          which is what :CartographMark does
  set_view      (unbound) the working-set altitude (:CartographWorkingSet)
  set_next      (unbound) next working-set member
  set_prev      (unbound) previous working-set member
  cone_in       (unbound) cone: what REACHES this (:CartographCone)
  cone_out      (unbound) cone: what this REACHES
>
    require('cartograph').setup { keys = { mark = ',m', set_view = ',M',
      set_next = ']w', set_prev = '[w', cone_in = ',c', cone_out = ',C' } }
<

THE LENSES OF AN ALTITUDE                                   *cartograph-lenses*

An altitude can show the same subject in more than one way. `cycle` (<Tab>)
moves between them, `cycle_back` (<S-Tab>) the other way, and the pane's winbar
names them so you never have to press a key to find out what is there:
>
    ⇥ statements [detail] lints
<
The bracketed one is in effect. An altitude with a single view says `— one view
here` rather than drawing nothing, because blank chrome cannot be told from
chrome that failed. The key is shown as you have it BOUND — remap `cycle` and
the strip prints your binding, not a Tab you would press in vain.

This table is checked against lua/cartograph/panes/symbols.lua by
tests/lensbar_spec.lua, so it cannot drift from the code.

  altitude      lenses ~
  fn            statements detail lints
  block         statements detail
  region        statements detail
  files         flat tree
  file          members live

  statements  each altitude's normal view: the code's statements in order
  detail      the fine-grained descendable elements a statement contains —
              arguments, conditions, var and field reads. A row here elides
              its TAIL to fit (see |cartograph-budget|); the full text is one
              hover away in the source pane
  lints       :CartographExpr's findings as ROWS instead of a scratch buffer.
              `l` on a finding descends into its actions (|cartograph-suppression|)
  flat        the file roster, alphabetical, shortest unique path suffix
  tree        the same files as an INCLUDE tree (or a load order, where the
              project declares one)
  members     what the file's module exposes
  live        what the RUNNING instance says it exposes — `self://` only, so
              it is offered at the file altitude only under that provider
              (|cartograph-providers|). Nothing on disk can answer it

Cycling FOLLOWS your position: the thing under the cursor is carried to its row
in the new lens. When it has no row there — an argument vanishing in
`statements` — it becomes a GHOST anchored to its enclosing statement, and
cycling back restores it exactly.

THE SUBJECT OF A ROW                                       *cartograph-subject*

`mark` and the cone verbs act on the row's SUBJECT — the node the row is about,
which is not always a node the row IS:

  1. the row's own symbol, at the file or working-set altitude
  2. else what the row REFERS to: a call site, an occurrence, or a folded
     usage group is about the function whose body contains it, so marking
     works while you traverse references
  3. else the altitude's own subject: the function you descended into, the
     entity whose callers you are reading. No row at those altitudes is a
     symbol, so without this, mark had nothing to act on and refused

Because 3 marks something with no row of its own to carry the ●, the verb says
which node it marked. A file row has no subject — a file is not a node — so
mark there reports that rather than guessing at its members. A "registered by"
row is the exception that looks like one: it names a registering MODULE, and a
module IS a node, so mark, cone and hover all act on it directly by rule 1.

5. TRANSACTIONS                                       *cartograph-transactions*

Every edit verb rides the same substrate:

  plan     computed against the CURRENT graph; holds refs (rename-tolerant
           identities), file stamps, the graph generation. Shown in the
           plan bar; nothing is written.
  verify   at apply time, late-bound: the generation must match, every ref
           must still resolve witness-clean, every touched file must be
           byte-identical to plan time (stamp CAS), no dirty buffers.
           Any drift REFUSES with its reason — a refusal costs a re-plan,
           never a corrupted write.
  journal  before-content recorded first (a create records absence);
           pending -> writes -> applied. A crash mid-apply leaves evidence
           and a manual rollback, never mystery.
  after    touched files splice back through the same refresh machinery
           every save uses; undo/redo walk the journal as a stack.

What a verb WRITES is only what it can prove complete. A lua move writes
the text, the new require line, and requalified call sites together — but
bare-name calls, shadowed aliases and the moved body's own references stay
HAZARDS: disclosed with counts, yours to finish.

6. HONESTY VOCABULARY                                      *cartograph-honesty*

  ~        name-matched (inferred): unique name, not proven by types
  dynamic  a call the graph knows it cannot see ($fn(), variable methods)
  frontier unparsed/unreachable territory shown AS territory (min.js,
           missing parsers, vendored bundles) — descend reaches in by
           text search
  torn     a def extracted from beyond a parse error: visible, jumpable,
           never name-matched (it escaped its context)
  refusal  ambiguity never picks a side — two candidates = no link. A
           refusal is a PLACE: descend an unresolved call to see the
           candidates it refused between and the rule (see below)
  alibi    why a function is not dead: a caller, a REGISTRATION (a
           dispatch table / load-time data / annotation — the fn view's
           "◆ registered by" descends into it), an entry point, or a
           visibility promise. No alibi ⇒ possibly dead

A row FITS, or it says so.                              *cartograph-budget*
The symbols pane has `symbols_width` columns of text (default 30; the gutter is
outside it) and 'wrap' is off, so a longer row would be cut by the editor with
no marker at all — the pane would silently withhold what it rendered. So a row
carries ONE identity that fits, and whatever does not fit is detail with a home
somewhere else:

  a file row shows the shortest path SUFFIX that is UNIQUE among the files on
  screen. Two railbot.lua in different directories each keep the directory that
  separates them; a basename unique on its own drops its prefix entirely.
  Descend (l) into the file and the dropped directory is the dim breadcrumb
  above the header. The path itself is never lost — hover, gf, staging and the
  source pane read the real path, never the label.

  …        an identity too long even on its own is elided IN THE MIDDLE, both
           ends kept (crash-site-…-machine.lua). Only an identity is ever
           elided, and never silently; an annotation moves or goes instead.

  free TEXT — a statement, a call, a condition — elides at the TAIL instead
  (`local vonnCharacter = playe…`), because a statement reads left to right and
  its front is what identifies it. The full text is never lost: every such row
  anchors to its source line, so the source pane holds it whole.

An EMPTY view states which KIND of empty it is. "no callers found — entry
point, or dynamically dispatched" is a computed absence: the call graph was
built and holds none. "⚠ index-only mode has no call graph" is an ABSENT
answer — shown as a frontier, with the count reading `unavailable` instead of
0 — because a thin index carries every file's definitions and no edges, so a
function with four callers would otherwise read as having none. The relation
altitudes (callers, occurrences, registered-by, refusals) and a var's usage
sites all make that distinction.

A SUPPRESSED finding is still counted.                *cartograph-suppression*
On the `lints` lens, `l` on a finding descends into its ACTIONS: the full
explanation the 30-column row could not carry, `suppress here`, and a `fix` row
that is always present and states its own unavailability with a per-rule reason
— an action list that omits the option it has not implemented says neither
"there is no safe rewrite" nor "nobody wrote one yet".

Suppressing appends `@cg-ignore: <rule>` to the reported line, and the reader
also honours it on a comment line directly above (blank lines and code stop the
walk). It is appended rather than inserted because inserting a line shifts
every range below it — the write would invalidate the map it was issued from.
Naming rules is what keeps one marker from silencing everything a line could
ever be flagged for; a bare `@cg-ignore` silences all of them. Unknown comment
syntax REFUSES rather than guessing, the write is journaled, so
|:CartographUndo| reverses it, and `un-suppress` is offered wherever a marker
is already present.

The count is never hidden: the lens says `N suppressed here` and
:CartographExpr lists each silenced finding with the marker that silenced it.
Otherwise "0 findings" would mean clean-or-hushed, which is the ambiguity this
whole section exists to remove.

7. CONFIGURATION                                            *cartograph-config*

setup() is optional; every field has a default: >

    require('cartograph').setup {
      cache   = false,
      exclude = { 'warpc' },
      mcp     = { game = { cmd = { 'my-mcp-server' } } },
    }
<
The options most worth knowing about. Each name below is checked to be a real
setup field (tools/docaudit.lua); the full set — around thirty, the rest being
tuning knobs — is documented where it lives, in lua/cartograph/config.lua, one
comment per field.

  option        what it sets ~
  keys          remap any binding — see |cartograph-keys|
  symbols_width the symbols pane's TEXT budget in columns (default 30; the
                gutter sits outside it, and the window is sized to fit both).
                Every row's identity is rendered to FIT this — see
                |cartograph-budget|
  entrypoints   path patterns for files EXPECTED to have no importer, so
                they classify 'entry' (▶) instead of 'orphan' (○)
  exclude       extra vendored directory NAMES to skip
  cache         per-file shard cache; warm opens
  parallel      worker processes for cold opens
  refresh       re-extract a file on save and splice it into the graph
  shapes        project-shape presets — see below
  discover      registry auto-discovery (Greenspun detection)
  unparsed      keep minified bundles as opaque frontier modules
  pins          human dispatch declarations: name the target of a
                dynamic call site the analysis cannot resolve
  bindings      cross-language string-key dispatch boundaries
  clangd        the clangd oracle for C/C++ (proves call edges)
  luals         the lua-language-server oracle for Lua
  profile       environment profiles: distilled stdlib/RBS signatures
  mcp           graph servers, { name = { cmd = {...} } }
  db            link sql:: entities to live tables
  fsm           the state-machine adapter
  factorio      the Factorio projection surface
  ecosystem_roots
                where an INSTALLED package ecosystem lives, keyed by
                ecosystem name ({ ['lua-factorio'] = { install = … } }).
                An override always wins; for a root the spec marks not
                derivable it is the only way the root can be known —
                Factorio's install is absent from every standard location
                on a machine that has the game's user dir, so nothing is
                guessed. :CartographRoster reports which roots resolved
                and how each was established

PROJECT SHAPES: marker files at the root (info.json + control.lua,
manage.py, package.json, wp-settings.php, …) preset what they honestly
imply — entry-point patterns, excludes; the node manifest's main/bin are
read as entry points. Presets are INERT analysis hints only: a shape
never wires runtime dialing (mcp/live/db), never overrides a key you set
in setup{}, and one root's presets are stripped before the next root's
open. `setup{ shapes = false }` disables; :CartographShapes explains
what matched and what it changed.

Complete per-project wirings (a Factorio mod with the live oracle, a
WordPress tree with the database link) live in examples/ — that is where
the non-inert configuration belongs.

8. PROVIDERS                                             *cartograph-providers*

  tree-sitter   directories; any language with a spec. All edges name-
                matched (~), capabilities partial by construction.
  dump          a neutral-schema JSON file (e.g. the lua-ls --graph CLI).
  mcp://name    a server tool returning the neutral schema; stamped
                sources cache like local files, stampless ones re-fetch.
  self://loaded the RUNNING nvim as one corpus: every loaded plugin's
                runtimepath unioned under a synthetic root, so a require
                from your config into a plugin — or plugin into plugin —
                resolves in a single graph. A session-scoped SAMPLE, not
                cached: the next launch may load a different set.
  tokens        stack languages (Forth, PostScript), which cannot have a
                faithful grammar even in principle — Forth's parsing
                words rewrite the syntax at runtime. Defs come from
                definer words; word mentions are ref EDGES, not call
                sites (`capabilities.calls` = aggregated). A root of
                these opens through it automatically. A MIXED root opens
                through tree-sitter and says how many dialect files it
                left out: the two providers promise different things
                about calls, so they are not merged into one graph.
                Saving a dialect file does not re-extract it.
  clangd        an ORACLE over the cpp skeleton: call edges proven via
                callHierarchy, only answered functions upgraded.

The prefixed targets listed here are checked against the ones :Cartograph
actually accepts (tools/docaudit.lua), so this list cannot offer a target that
does not work, nor omit one that does.

9. HEALTH                                                   *cartograph-health*

`:checkhealth cartograph` reports nvim version, installed parsers (each
missing one is a language that opens as frontier modules), nvim-treesitter
presence (vue/svelte + worker runtimepath), the cache codec fast path, and
the optional oracles (clangd, git).
